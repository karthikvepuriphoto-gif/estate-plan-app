# Apps Script version

**Design:** Google sign-in comes free (the web app runs *as the user accessing it*). Answers → a Google Sheet "Estate Plan Answers"; drafts → Google Docs; both in a Drive folder "Estate Plan Drafts" the user owns. Spouses collaborate via **Share with spouse** (`shareWithSpouse(email)`), which shares the folder.

**Scopes (appsscript.json):** `drive.file` + `userinfo.email` only, both non-sensitive. That's why Code.gs uses the **Advanced Drive service (v3)** for everything (create folder, create the Sheet from CSV, read it via export, create Docs from HTML) instead of SpreadsheetApp/DocumentApp/DriveApp, which would pull in broad sensitive/restricted scopes. Caveat of `drive.file`: the spouse's copy of the app can't see a folder shared *to* them until they select it once with Google Picker (then call `useSharedFolder(id)`); Picker is a planned follow-up.

**Files:** `Code.gs` (server), `Index.html` + `Styles/Data/Storage/Flow/Templates/App.html` (same UI as the GitHub Pages preview, generated by `python3 build_apps_script.py` — don't hand-edit them). The UI's storage adapter switches to `google.script.run` automatically.

## Deploy
**Option A – copy/paste:** script.google.com → New project → Project Settings → "Show appsscript.json" → paste ours. Create each file with the same name and paste content. Services (+) → Drive API v3 (identifier `Drive`). Deploy → New deployment → Web app → Execute as *User accessing*, Access *Anyone with Google account* → copy the /exec URL.
**Option B – clasp:** `npm i -g @google/clasp && clasp login && clasp create --type webapp --title "Estate Plan Drafter" --rootDir apps-script && clasp push && clasp deploy`.
Then link a standard Cloud project and set up the OAuth consent screen (see ../docs/marketplace-checklist.md).

**Unverified-app warning:** until brand verification, users may see "Google hasn't verified this app" → Advanced → Go to Estate Plan Drafter. With only non-sensitive scopes, there's no 100-user cap.

**Publishing options:** (1) share the web-app URL (phase 1); (2) Workspace add-on — `onHomepage()` is already in Code.gs; add an `addOns` block (`common.homepageTrigger.runFunction: "onHomepage"`) to the manifest and deploy as add-on; (3) Marketplace listing of the web app or add-on via the Marketplace SDK. Same code for all three.
Not deployed or run against Google; linted locally only (`node --check`).
